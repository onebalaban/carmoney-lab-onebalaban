# MILEAGE
## Входит / не входит
Входит понижение approve до review по пробегу; не входят изменения LTV, БД, UI, reason codes.
Источник: intent_MILEAGE.md, решения протокола Grill Me.

| REQ | Требование | AC |
|---|---|---|
| REQ-MILEAGE-01 | При пробеге <=400000 решение по LTV сохраняется | AC-MILEAGE-01: 399999 и 400000 при LTV 50 дают approve, лимит 450000 |
| REQ-MILEAGE-02 | Допустимый пробег >400000 понижает approve до review | AC-MILEAGE-02: 400001 и 500000 при LTV 50 дают review, лимит 0 |
| REQ-MILEAGE-03 | Более строгий reject не отменяется | AC-MILEAGE-03: 400001 при LTV 95 даёт reject; LTV 75 остаётся review |
| REQ-MILEAGE-04 | Неизвестный/пустой/нецелый пробег не принимается | AC-MILEAGE-04: отсутствие, null, пустая строка, abc, 1.5, true, массив дают ValidationException с mileage |
| REQ-MILEAGE-05 | Валидационный максимум сохраняется | AC-MILEAGE-05: -1 и 500001 — ошибка; 0 и 500000 допустимы |

400000 — задание; 500000 и 0 — backend/config/rules.php и ApplicationValidator.php; LTV 50/75/95 и суммы — синтетические тестовые примеры, не новые пороги.
Уточнение безопасности входа: пустые и нечисловые значения нельзя приводить к нулю, иначе обходится намерение проверки.
