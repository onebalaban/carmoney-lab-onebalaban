# 2.2.2: сравнение формата ревью
Просьба: «Посмотри backend/src/Repository/ApplicationRepository.php перед мержем».

## Без шаблона
В listApplications статус конкатенируется в SQL. save выполняет три INSERT без транзакции. В списке N+1 запросы. Нужны параметры, транзакция и JOIN.

## По скиллу
- [P1] backend/src/Repository/ApplicationRepository.php:92. GET /api/applications?status=decided%27%20OR%201%3D1%20--%20 превращает фильтр в условие, истинное для всех строк. SQL-инъекция позволяет обойти фильтр. Исправление: bind :status. Проверка: строка с кавычкой не возвращает все заявки и не ломает SQL.
- [P2] backend/src/Repository/ApplicationRepository.php:24. Первый INSERT уже сохранён, когда второй или третий завершится исключением. Частичная заявка остаётся без автомобиля/решения. Исправление: транзакция с rollback. Проверка: искусственная ошибка третьего INSERT оставляет ноль новых строк.
- [P3] backend/src/Repository/ApplicationRepository.php:101. Для N заявок выполняется 1+2N запросов; при 50 — 101 запрос. Исправление: JOIN или пакетное чтение. Проверка: число запросов постоянно при росте страницы.
Вердикт: нужны исправления P1/P2 до мержа соответствующей функциональности. Непроверенное: интеграционный прогон MySQL.

Разница: появились воспроизводимые сценарии, приоритеты, строки и способ проверки вместо общего списка замечаний. Изменения кода не входят в ревью.
