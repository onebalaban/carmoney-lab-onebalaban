# Замысел
Проверять заявки на автозаём по риск-правилам до передачи андеррайтеру и сохранять результат с причинами.
# Зачем
Сделать проверку воспроизводимой и направлять сложные случаи риск-менеджеру.
# Constraints
- Лимиты по типу: легковой 2000000 ₽, коммерческий 3000000 ₽, мотоцикл 500000 ₽. Источник: REG-RISK-02 п.2.3.
- Возраст больше 20 лет — отказ. Источник: CASE-01 §2 П-3.
- Сумма ниже 50000 ₽ — техническая ошибка. Источник: CASE-01 §2 П-4.
- Проверяются все правила, сохраняется полный перечень причин. Источник: REG-RISK-02 п.2.1/2.7.
- Два и более срабатывания требуют эскалации. Источник: REG-RISK-02 п.2.7.
# Open questions
1. Открыт, риск-менеджер: лимит займов 2 по регламенту или 3 по тикету? При active_loans=2 отклонять заявку или допускать проверку до создания третьего договора? В материалах это противоречит примеру A-1002.
2. Открыт, риск-менеджер: эскалация является отказом (П-5) или оставляет заявку в работе (CONF-escalation)?
3. Открыт, продукт: неизвестный тип авто и недоступные данные о займах — ошибка, review или отказ?
4. Открыт, риск: порядок причин, срок эскалации «в течение суток», ручные исключения и полномочия.
# Не входит
ПДн, реальные заявки, выдача денег, дополнительные поручители, изменение действующих риск-порогов сервиса, реализация спорных правил без решения владельца.

# Интервью по материалам
Что автоматизировать? Проверку до одобрения (§1).
Откуда числа? Из регламента и списка П-1..П-5, не из статистики выдач.
Что делать с конфликтами? Не выбирать молча; вопросы 1–4 блокируют соответствующие задачи.
Что считается результатом? Spec и issues с проверяемыми AC; runtime в этом эпике не меняется.
